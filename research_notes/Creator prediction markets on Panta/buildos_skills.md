## 1. What does kaizen-mega prescribe as the overall workflow, rules, preferred stack, and routing, and how do the skills map onto this build?

### Takeaway
kaizen-mega is a router, not a builder. It loads hard rules (no AI co-author trailers, no assistant mentions in artifacts, no mock metrics or fake social proof, MVP only), runs a 7-phase loop (intent → plan → validate → design → build → audit → ship), and routes web UI to `frontend-design-guidelines`/`frontend-design`/`brand-design`/`design-taste`, Solana MVPs to `scaffold-project`/`build-with-claude`/`build-defi-protocol`/`launch-token`/`build-mobile`, and research to `validate-idea`/`find-next-crypto-idea`/`competitive-landscape`/`colosseum-copilot`/`defillama-research`. It does not set a stack itself. The stack comes from `frontend-design-guidelines` (Next.js App Router + TS + Tailwind + shadcn/ui) and `scaffold-project` (integrate-first: Next.js + protocol SDK, no Anchor). Nothing in kaizen-mega mentions Panta, prediction markets, Blinks or social sharing.

## 2. What do the Solana/crypto skills prescribe for stack, wallet/signing patterns, and pitfalls?

### Takeaway
The Solana skills agree on a few defaults. Integrate an existing protocol before writing Anchor code (here, the Panta API). Use Next.js, Helius RPC, `@solana/kit` for new code, and Wallet Standard auto-detect, plus an embedded-wallet ramp (Privy/Dynamic) for newcomers. Test on devnet first and ship in small 1–2-hour milestones. Transactions get strict UX: preview → simulate → explicit sign → submitting/confirming/confirmed timeline, and a wallet rejection is not an error. The listed pitfalls are blockhash expiry, ATA creation cost, mint decimals, rent, priority fees, the 1232-byte tx size, and RPC 429s. No skill covers Solana Actions/Blinks, a Privy SDK integration, or Panta. `designing-application-transactions` is about CockroachDB, not Solana.

## 4. Which UI/design rules should govern a mobile-first social UI (typography, color, motion, components, anti-patterns)?

### Takeaway
There is a strong consensus core. Use tokens only, one accent, WCAG AA, 44×44 px touch targets, skeleton/empty/error states, `font-mono tabular-nums` numbers, motion under ~300 ms using transform/opacity with `prefers-reduced-motion`, mobile-first testing at 375 px, bottom sheets on mobile, `min-h-[100dvh]`, and no fake data. `design-taste` names "Soft Consumer" (Phantom/Backpack/Coinbase, rounded 12–16 px, spacious, progressive disclosure) as the consumer-wallet reference. `brand-design` ships consumer/social palettes ("Coral Gossip — A group chat that never dies", "Peach Comfort — Something you send your friends") and a "crypto-native consumer" font pair (Plus Jakarta Sans + JetBrains Mono). The skills openly conflict on Inter, the icon library (lucide vs Phosphor), gradients, glass, ease-in exits, and perpetual animation. `brand.md` is meant to be the tie-breaker.

### Cited Findings

## 8. Which skills are outdated, internally inconsistent, or in conflict with each other for this build?

### Takeaway
The repo is a merged dump of several authors' skills (superstack/solana-new, Emil Kowalski, Taste-skill-style "anti-slop" prompts, Hermes, OKX, HyperFrames). The conflicts are concrete: fonts (Inter allowed vs banned), icons (lucide default vs banned), gradients/glass (allowed for warmth vs banned), exit easing (ease-in vs never ease-in), motion intensity (perpetual vs <300 ms purposeful), wallet SDK default, wallet gating, light vs dark defaults, and the two video stacks (Remotion vs HyperFrames). Many cross-references point to files and skills that are not in the clone.
